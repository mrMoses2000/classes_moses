# Архитектура сайта «Робот и код»

## Граница первой версии

Сайт нужен для очного урока с одним учеником и преподавателем. Сегодня он должен работать в браузере на Ubuntu, по возможности без интернета после установки. Первая версия включает **полноценное первое занятие**, экран преподавателя и сохранение хода урока на этом устройстве. Остальные темы показываются как дорожная карта; их задания добавляются последовательно, после проверки первого урока на ребёнке.

Сайт не компилирует произвольный C в браузере, не принимает файлы ученика, не требует регистрации и не вызывает ИИ во время занятия. Подключение GCC, Arduino и сетевых упражнений относится к дальнейшим версиям. AGY CLI участвует в подготовке и разработке материалов преподавателем; его вывод не показывается ребёнку как готовое решение.

## Компоненты и поток данных

```text
Преподаватель и ученик → браузер → статический сайт
                                  ├─ сценарий урока и задания (данные)
                                  ├─ симулятор робота (детерминированные правила)
                                  ├─ редактор команд и исполнение по шагам
                                  ├─ обратная связь и экран рефлексии
                                  └─ локальное сохранение прогресса

AGY CLI → готовит новые задания/проверяет качество → файлы проекта → сборка сайта
```

Один deployment unit: собранный статический сайт. Для разработки достаточно Node и локального dev server. Для показа на другой машине в той же сети можно раздать собранные файлы обычным статическим сервером. До проверки доступности использовать `localhost` на Ubuntu; если нужно открыть на другом устройстве, проверять адрес, маршрутизацию и firewall отдельно.

**Хранение:** в `localStorage` сохранять только номер задания, список команд и отметки прохождения, с версией формата. Если хранилище недоступно, урок работает в памяти. ФИО, почта, видео, телеметрия и ключи не нужны. Учитель может сбросить прогресс после подтверждения. Кэш внешних данных отсутствует.

**Секреты и ИИ:** ключи AGY остаются только в CLI окружении преподавателя. В frontend их не помещать. API ИИ для ученика не делать. Никаких серверных retry для MVP нет; повторный запуск программы робота должен быть идемпотентным и всегда начинаться из начальной позиции задания.

**Сбои и наблюдаемость:** при ошибке маршрута показывать понятную причину («Робот упёрся в стену на шаге 4») и подсветить команду. Ошибка сохранения не блокирует игру. Во время разработки писать ошибки в консоль; интерфейс ученика не показывает stack trace. Зависимость от сети во время урока исключить.

## Структура первого экрана

1. Крупная задача: «Доставь робота к маяку» и один понятный критерий успеха.
2. Поле 5×5 с роботом, целью и 0–2 препятствиями. Координатные числа ребёнку не нужны.
3. Панель из трёх команд: «Шаг», «Повернуть налево», «Повернуть направо». Команды добавляются кликом/клавиатурой; drag and drop необязателен.
4. Видимый список программы: порядок, удаление команды, перемещение вверх/вниз, активная команда при запуске.
5. Одно главное действие «Запустить». Рядом «По шагам» и «Сбросить попытку».
6. Короткий ответ после запуска: достиг цели, остановился у стены, вышел за поле или закончились команды. Он должен подсказывать, где искать ошибку, не выдавая всю последовательность.
7. «Показать код» после попытки: отображает эквивалент вызовов команд в C-подобной записи и не притворяется настоящей компилируемой программой.
8. Отдельное раскрывающееся меню преподавателя: цель, ожидаемая трудность, вопросы вместо подсказки, признак понимания.

## Три задания сегодня

Использовать единый детерминированный движок. Направления и координаты — внутренние данные; в UI они не нужны.

| Задание | Поле | Что делает ученик | Что проверяется |
| --- | --- | --- | --- |
| 1. Прямой путь | старт (0,2), взгляд на восток; цель (3,2), без стен | составляет три шага | порядок и количество команд |
| 2. Обход | старт (0,2), взгляд на восток; стена (1,2); цель (2,2); клетки 5×5 | выбирает обход через верх или низ | повороты и предсказание траектории |
| 3. Почини маршрут | старт (0,2), взгляд на восток; цель (2,2), без стен; заготовка `шаг, поворот налево, шаг` | исправляет лишний поворот и при необходимости добавляет шаг | поиск причины ошибки, а не подбор вслепую |

В задании 2 принимать любой корректный путь без столкновений; не сравнивать программу с одним эталонным списком. В задании 3 программа может иметь разные корректные исправления. Исполнение ограничить разумным количеством команд (например, 50), чтобы случайная длинная программа не подвесила UI.

## Дизайн

Образ: настольная инженерная мастерская для ребёнка, а не «детский сад» и не панель администратора. Светлый тёплый фон, чёткая квадратная сетка, один выразительный акцент для робота, другой — для цели. Цвет не должен быть единственным носителем смысла: у робота стрелка направления, у цели подпись/форма, у препятствия узнаваемый контур. Крупные элементы управления, короткие русские фразы, видимое состояние фокуса. На экране 1366×768 поле и программа должны помещаться без прокрутки основной задачи; на узком экране блоки идут последовательно. Не применять мигание, шум, таймер или конфетти после каждого клика.

Адаптация набора UX/UI из `/Users/mosesvasilenko/ux-ui-agent-skills` (macOS) или `/home/moses/ux-ui-agent-skills` (Ubuntu): читать `CLAUDE.md` как справочник, но применять только нужные разделы `accessibility/cognitive.md`, `content/voice-tone.md`, `accessibility/wcag-checklist.md`, `taste/design-taste.md`, `tokens/`. Не копировать Claude-specific команды, плагины и полный набор 138 дизайн-систем в проект. Сделать маленький набор CSS-переменных по назначению (фон, текст, акцент, ошибка, успех, отступы, радиусы), проверить контраст и работу с клавиатуры. Текст интерфейса адресовать ребёнку; подсказки преподавателя держать отдельно.

## Очерёдность реализации AGY

1. Сначала рабочий движок трёх заданий, клавиатурный ввод, объяснимые ошибки и локальное сохранение.
2. Затем экран преподавателя, «Показать код», экран завершения и адаптивный дизайн.
3. Потом тестирование в реальном браузере и исправление найденного. Отдельно проверить, что прямой путь, обход, неверный маршрут и исправление дают ожидаемые состояния.
4. После первого урока — выводы по наблюдениям и только затем следующие модули. Не строить сегодня общий LMS, аккаунты, API ИИ или C sandbox.

## Критерии готовности

- Ученик без входа в аккаунт открывает урок и проходит задания 1–3.
- Ученик видит, какая команда сейчас выполняется; может запустить заново и пройти по шагам.
- Неверная программа объясняет ошибку и позволяет исправить список команд без потери работы.
- Перезагрузка страницы возвращает текущую программу и прогресс, если браузер разрешает localStorage.
- Все действия доступны клавиатурой; на телефоне и ноутбуке нет горизонтальной прокрутки основной области.
- Сборка и проверка проходят, AGY сообщает фактические команды и результаты, а преподаватель открывает сайт на Ubuntu до урока.
