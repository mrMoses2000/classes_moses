# Занятие 12: «Arduino: Ввод, тактовая кнопка и дребезг контактов — физический бампер и реакция»

Сценарий очного занятия для способного ученика 4 класса (55–60 минут)  
**Уровень сложности:** Профессиональный инженерный (схемотехника цифрового входа, подтягивающий резистор `INPUT_PULLUP`, физический дребезг контактов).  
**Траектория:** Этап 3. «Компьютер и Arduino» → Обработка дискретных внешних сигналов и датчиков.

---

## 1. Место урока в общей траектории

- **Конечная способность из `LEARNING_VISION.md`:** Подключать датчик-кнопку к Arduino; понимать проблему «плавающего пина» (floating pin) и активировать встроенную подтяжку `INPUT_PULLUP`; программно устранять физический дребезг контактов (bounce); связывать нажатие физического бампера с ветвлением `if / else` в скетче.
- **Текущий этап:** Этап 3 («Компьютер и Arduino»).
- **Прошлый освоенный навык (Занятие 11):** Ученик умеет управлять пинами на вывод (`OUTPUT`), зажигает светодиоды и собирает цепи на breadboard.
- **Причина выбора темы:** Вывод (`OUTPUT`) — это голос робота (свет, звук, моторы). Но роботу нужны **органы чувств** — входные сигналы (`INPUT`). Мы подключаем тактовую кнопку как контактный бампер робота. Здесь ученик сталкивается с двумя фундаментальными законами электроники: почему висящий в воздухе провод ловит наводки как антенна и почему упругие металлические контакты дребезжат при ударе, порождая десятки ложных срабатываний за миллисекунды.

---

## 2. Главная учебная цель и проверяемый результат

- **Главная учебная цель:** Освоить считывание цифрового сигнала функцией `digitalRead()`, понять схему подтяжки к питанию `INPUT_PULLUP` (инверсная логика: нажато = `LOW`, отпущено = `HIGH`) и реализовать программный алгоритм антидребезга (debounce).
- **Проверяемый результат (действие ребёнка без подсказки):**
  1. Подключает кнопку двумя проводами: один к цифровому пину 2, второй — к `GND`.
  2. В коде пишет `pinMode(2, INPUT_PULLUP);` и объясняет, почему на не нажатой кнопке читается `HIGH`: *«Внутри микроконтроллера включился резистор, который подтягивает провод к 5 Вольтам. А когда я жму кнопку — провод замыкается на землю GND и напряжение падает в ноль (LOW)»*.
  3. В задаче счётчика кликов наблюдает эффект дребезга (одно нажатие прибавляет сразу +5 к счёту) и устраняет его фильтром задержки или фиксацией момента смены фронта.

## 4. Практические задания со скетчами

### Задание 1. «Бортовой бампер с прямой реакцией»
- **Схема:**
  - Кнопка: один вывод на `Pin 2`, диагональный вывод на `GND`.
  - Светодиод тревоги: `Pin 12` через резистор 220 Ом на `GND`.
- **Скетч (`bumper.ino`):**
  ```cpp
  const int BUMPER_PIN = 2;
  const int ALARM_LED  = 12;

  void setup() {
      pinMode(BUMPER_PIN, INPUT_PULLUP);
      pinMode(ALARM_LED, OUTPUT);
  }

  void loop() {
      int button_state = digitalRead(BUMPER_PIN);

      // При INPUT_PULLUP: LOW означает контакт замкнут (бампер нажат!)
      if (button_state == LOW) {
          digitalWrite(ALARM_LED, HIGH); // Столкновение! Включить маяк
      } else {
          digitalWrite(ALARM_LED, LOW);  // Путь чист
      }
  }
  ```

### Задание 2. «Исследование дребезга: счётчик кликов в Serial-монитор»
- **Скетч регистрации микро-отскоков (`bounce_test.ino`):**
  ```cpp
  const int BUTTON_PIN = 2;
  int click_count = 0;
  int last_state = HIGH;

  void setup() {
      Serial.begin(9600);
      pinMode(BUTTON_PIN, INPUT_PULLUP);
      Serial.println("=== ТЕСТЕР ДРЕБЕЗГА МЕХАНИЧЕСКИХ КОНТАКТОВ ===");
  }

  void loop() {
      int current_state = digitalRead(BUTTON_PIN);

      // Ловим переход из отпущенного (HIGH) в нажатое (LOW)
      if (last_state == HIGH && current_state == LOW) {
          click_count++;
          Serial.print("Фронт сигнала зафиксирован! Счётчик: ");
          Serial.println(click_count);
      }
      last_state = current_state;
  }
  ```
- **Результат наблюдения:** Ученик своими глазами видит хаотичные всплески счётчика при каждом нажатии.

### Задание 3. «Надёжный антидребезг (Программный фильтр)»
- **Скетч с подавлением дребезга (`debounced_button.ino`):**
  ```cpp
  const int BUTTON_PIN = 2;
  int click_count = 0;
  int last_stable_state = HIGH;

  void setup() {
      Serial.begin(9600);
      pinMode(BUTTON_PIN, INPUT_PULLUP);
      Serial.println("=== ФИЛЬТР АНТИДРЕБЕЗГА АКТИВИРОВАН ===");
  }

  void loop() {
      int reading = digitalRead(BUTTON_PIN);

      // Если сигнал изменился, ждём 40 миллисекунд, пока утихнет вибрация контактов:
      if (reading != last_stable_state) {
          delay(40); // Время затухания механического звона пластин
          reading = digitalRead(BUTTON_PIN); // Читаем повторно

          if (reading == LOW && last_stable_state == HIGH) {
              click_count++;
              Serial.print("[СТАБИЛЬНЫЙ КЛИК] Всего: ");
              Serial.println(click_count);
          }
          last_stable_state = reading;
      }
  }
  ```

## 7. Выходной вопрос и 4 критерия наблюдения

### Краткий выходной вопрос:
> *«Что такое дребезг контактов и почему микроконтроллер без фильтра считает одно нажатие за десяток кликов?»*  
> *(Ожидаемый ответ: «Металлические контакты внутри кнопки при ударе пружинят и искрят микро-отскоками. Микроконтроллер работает со скоростью 16 миллионов тактов в секунду и успевает посчитать каждый отскок как отдельное нажатие»)*.

### 4 наблюдения преподавателя:
1. **Понимание INPUT_PULLUP:** Понимает, почему кнопка подключается к пину и `GND`, а не к `5V`.
2. **Инверсная логика:** Не путает `LOW` (нажато) и `HIGH` (отпущено).
3. **Осознание физики сигнала:** Понимает реальную природу дребезга контактов.
4. **Работа с Serial:** Уверенно пользуется монитором последовательного порта для отладки.
