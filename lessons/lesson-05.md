# Занятие 5: «От блоков к тексту — терминал команд, синтаксис и разбор ошибок»

Сценарий очного занятия для способного ученика 4 класса (50–60 минут)  
**Уровень сложности:** Высокий (переход от визуального интерфейса к печати команд, чтение логов парсера).  
**Траектория:** Этап 2. «Текст и C на компьютере» → Знакомство с командной строкой Linux, синтаксисом и компиляцией.

---

## 1. Место урока в общей траектории

- **Конечная способность из `LEARNING_VISION.md`:** Пользоваться текстовым редактором и терминалом как естественными инструментами; при возникновении синтаксической ошибки читать номер строки и сообщение компилятора, локализовать опечатку и исправлять её без чужих подсказок.
- **Текущий этап:** Начало Этапа 2 («Текст и C на компьютере»).
- **Прошлый освоенный навык (Занятия 1–4):** Полное владение базовой алгоритмикой (линейные последовательности, циклы, ветвления `if/else`, переменные состояния).
- **Причина перехода к тексту:** Кнопки и блоки удобны для первого знакомства, но ни один реальный марсоход, операционная система или микроконтроллер не программируются перетаскиванием картинок. Блоки скрывают реальную работу компьютера, ограничивают скорость и не дают почувствовать строгость грамматики языка. Мы открываем текстовый терминал: теперь каждую команду ученик набирает пальцами на клавиатуре.

---

## 2. Главная учебная цель и проверяемый результат

- **Главная учебная цель:** Преодолеть психологический барьер перед текстовым вводом: освоить синтаксические правила (регистр букв, аргументы в скобках, разделитель точка с запятой `;`) и научиться осознанно читать сообщения об ошибках парсера.
- **Проверяемый результат (действие ребёнка без подсказки):**
  1. При получении ошибки `SyntaxError: Unexpected token 'STEP' on line 3` ребёнок не паникует, а сразу смотрит на строку 3 и объясняет: *«Я забыл точку с запятой на строке 2 или опечатался в слове»*.
  2. Различает два типа ошибок: **синтаксическая** (программа вообще не запускается, потому что компьютер не понял слова) и **логическая** (программа запустилась, но робот приехал не туда).
  3. Уверенно использует клавиши клавиатуры: скобки `()`, кавычки `""`, точку с запятой `;`, табуляцию и стрелки навигации.

## 4. Три интерактивных задания (Повышенная сложность)

### Задание 1. «Первый скрипт: чистота синтаксиса»
- **Цель:** Написать первую работающую текстовую программу без синтаксических сбоев.
- **Поле (5×5):**
  - Старт: `(0, 0)`, направление: `EAST`.
  - Маяк: `(2, 2)`.
  - Препятствие: скала на `(1, 0)` и `(1, 1)`.
- **Требуемый текст программы:**
  ```text
  turn_right();
  step(2);
  turn_left();
  step(2);
  ```
- **Критерий успеха:** Скрипт парсится без единой ошибки с первого или второго запуска; робот успешно достигает маяка.

### Задание 2. «Охота на синтаксические баги» (Глубокая отладка)
- **Цель:** Научиться расшифровывать сообщения парсера и компилятора.
- **Исходный испорченный текст:**
  ```text
  1: step();
  2: Turn_left();
  3: step(2)
  4: turn_right();
  5: step(
  ```
- **Диагностическая карта ошибок:**
  - Строка 2: `Unknown command 'Turn_left'. Did you mean 'turn_left'? (case-sensitive)`.
  - Строка 3: `Expected ';' before 'turn_right' on line 4`.
  - Строка 5: `SyntaxError: Unexpected end of file, expected ')' and ';'`.
- **Действие ученика:** Прочитать каждую строчку лога, перейти на указанную координату и исправить дефект.

### Задание 3. «Скоростной маршрут с параметрами»
- **Цель:** Преодолеть длинный периметр поля, используя аргументы функций `step(N)` и `turn(DIR, DEGREES)`.
- **Поле (5×5):** Обход по границе от `(0,0)` до `(4,4)` через внешний контур.
- **Ограничение:** Не более 6 строк кода в файле.
- **Решение:**
  ```text
  step(4);
  turn_right();
  step(4);
  ```

## 6. Дифференциация и развитие

- **Супер-вызов «Комментарии в коде»:** Показать, как с помощью символов `//` программисты оставляют записки себе и коллегам, которые компилятор полностью игнорирует:
  ```c
  // Это опасный участок около скалы:
  turn_right(); // поворачиваем к безопасному проходу
  ```
- **Задача на грамматику:** Почему парсер иногда жалуется на строку 4, если точка с запятой пропущена в строке 3? (Потому что компилятор читает код сплошным потоком и понимает, что команда не закончилась, только когда спотыкается о следующее слово!).

## 7. Выходной вопрос и 4 критерия наблюдения

### Краткий выходной вопрос:
> *«В чём разница между синтаксической ошибкой и логической ошибкой? Какую из них компилятор найдёт сам, а какую придётся искать тебе?»*  
> *(Ожидаемый ответ: «Синтаксическую ошибку компилятор видит сразу сам — это нарушение правил написания, опечатка или пропущенная точка с запятой. А логическую ошибку компилятор не видит, потому что программа написана грамотно, но делает не то, что нужно нам»)*.

### 4 наблюдения преподавателя:
1. **Чтение логов:** Ищет номер строки в сообщении об ошибке, а не хаотично меняет весь код.
2. **Слепая печать:** Уверенно находит спецсимволы `;`, `()`, `{}` на клавиатуре.
3. **Регистрозависимость:** Понимает разницу между `step()` и `STEP()`.
4. **Спокойствие при ошибке:** Воспринимает `SyntaxError` как точную подсказку компьютера, а не как неудачу.

## 8. Необходимые материалы и консольный код

1. Ноутбук с Ubuntu Linux и терминалом.
2. Редактор кода (VS Code, Nano или встроенный текстовый редактор симулятора).
3. **Демонстрационный файл на языке Си (`robot.c`):**
   ```c
   #include <stdio.h>

   void step(int count) {
       printf("[РОБОТ] Сделано шагов: %d\n", count);
   }

   void turn_left() {
       printf("[РОБОТ] Поворот налево на 90 градусов\n");
   }

   int main() {
       // Первая настоящая программа:
       step(2);
       turn_left();
       step(3);
       return 0;
   }
   ```
