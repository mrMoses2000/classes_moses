## 1. Место урока в общей траектории

- **Конечная способность из `LEARNING_VISION.md`:** Создавать компилируемую программу на C с разделением логики на независимые функции; передавать параметры по значению и возвращать результат через `return`; объяснять, почему переменная внутри функции «не видна» в `main()`, и проектировать понятную архитектуру без опасных глобальных переменных.
- **Текущий этап:** Завершающий этап работы с чистым C на компьютере перед изучением аппаратного устройства процессора и переходом к плате Arduino.
- **Прошлый освоенный навык (Занятия 6–8):** Ученик умеет писать линейный код, ветвления и циклы внутри одной большой функции `main()`.
- **Причина выбора темы:** Когда программа превышает 50–100 строк, писать всё в одной функции `main()` становится невыносимо: код превращается в «макароны» (spaghetti code), в нём легко запутаться и невозможно переиспользовать удачные решения. Функция — это **персональный супер-инструмент**: один раз написали математику расчёта расхода топлива или мигания аварийным сигналом — и вызываем её одной короткой строчкой из любого места программы!

## 2. Главная учебная цель и проверяемый результат

- **Главная учебная цель:** Освоить создание собственных функций: понять разницу между объявлением, определением и вызовом функции, научиться передавать входные аргументы и забирать вычисленное значение через оператор `return`.
- **Проверяемый результат (действие ребёнка без подсказки):**
  1. Самостоятельно описывает сигнатуру функции: `int calculate_fuel(int distance, int weight)` и объясняет, что первое слово `int` — это тип результата, а слова в скобках — входные ингредиенты.
  2. При попытке напечатать переменную из чужой функции в `main()` видит ошибку `error: ‘fuel’ undeclared here` и объясняет правило области видимости (scope): *«Эта переменная родилась внутри функции calculate_fuel, там она и живёт. Снаружи main() её не видит!»*.
  3. Использует возвращаемое значение функции в арифметических выражениях и проверках `if (calculate_fuel(100, 5) > battery_level)`.

## 4. Три практических задания

### Задание 1. «Баллистический калькулятор торможения»
- **Файл:** `~/robot_lab/physics.c`
- **Код:**
  ```c
  #include <stdio.h>

  // Функция расчёта тормозного пути по формуле: S = (V * V) / 10
  int calc_braking_distance(int speed_kmh) {
      int distance = (speed_kmh * speed_kmh) / 10;
      return distance;
  }

  int main() {
      printf("=== ТОРМОЗНОЙ КАЛЬКУЛЯТОР ШАССИ ===\n");

      for (int v = 10; v <= 50; v += 10) {
          int s = calc_braking_distance(v);
          printf("При скорости %2d км/ч тормозной путь = %3d м\n", v, s);
      }

      return 0;
  }
  ```
- **Результат:** Чёткая таблица тормозного пути: 10 км/ч ➔ 10 м, 50 км/ч ➔ 250 м (квадратичная зависимость!).

### Задание 2. «Предикат готовности реактора»
- **Файл:** `~/robot_lab/reactor.c`
- **Задача:** Написать функцию `int is_engine_ready(int fuel, int temp, int pressure)`, которая возвращает 1, только если ВСЕ три параметра идеальны: топлива > 20%, температура < 90°C и давление от 100 до 150 кПа.
- **Код:**
  ```c
  #include <stdio.h>

  int is_engine_ready(int fuel, int temp, int pressure) {
      if (fuel > 20 && temp < 90 && (pressure >= 100 && pressure <= 150)) {
          return 1; // Все системы в норме
      }
      return 0;     // Не готов к пуску!
  }

  int main() {
      int f = 45;
      int t = 75;
      int p = 120;

      if (is_engine_ready(f, t, p)) {
          printf("[СТАТУС: ГОТОВ] Главный маршевый двигатель запущен!\n");
      } else {
          printf("[ОТКАЗ] Параметры двигателя выходят за границы допуска!\n");
      }

      return 0;
  }
  ```

### Задание 3. «Устранение ошибки видимости (Scope bug)»
- **Файл:** `~/robot_lab/scope_error.c`
- **Код с ошибкой:**
  ```c
  #include <stdio.h>

  void calculate_energy() {
      int total_power = 100 - 15;
  }

  int main() {
      calculate_energy();
      // БАГ: переменная total_power не существует в функции main!
      printf("Остаток энергии: %d\n", total_power);
      return 0;
  }
  ```
- **Ошибка компилятора:** `error: ‘total_power’ undeclared (first use in this function)`.
- **Действие ученика:**
  1. Изменить тип функции с `void` на `int`.
  2. Добавить `return total_power;` внутри функции.
  3. В `main()` поймать результат: `int p = calculate_energy(); printf("...", p);`.

## 6. Дифференциация и развитие

- **Супер-вызов «Прототипы функций»:** Показать, почему компилятор требует объявлять функцию ДО её вызова или использовать прототип в начале файла:
  ```c
  int calc_braking_distance(int speed); // прототип: обещание компилятору
  ```
- **Философия чистых функций:** Объяснить, почему функция, которая зависит только от своих аргументов и ничего не ломает вокруг (чистая функция), считается идеалом надёжности в авиации и космических аппаратах.

## 7. Выходной вопрос и 4 критерия наблюдения

### Краткий выходной вопрос:
> *«Зачем нужны функции в программе, если можно было бы всё написать подряд в одной функции main()?»*  
> *(Ожидаемый ответ: «Чтобы не повторять один и тот же код, не делать глупых ошибок и чтобы программа была разбита на понятные кусочки, каждый из которых решает свою задачу»)*.

### 4 наблюдения преподавателя:
1. **Понимание return:** Понимает, что `return` возвращает значение и немедленно завершает работу функции.
2. **Передача аргументов:** Не путает формальные параметры в заголовке и фактические значения при вызове.
3. **Область видимости:** Чётко осознаёт локальность переменных внутри `{}`.
4. **Архитектурная чистота:** Сам предлагает выделить повторяющийся фрагмент в отдельную функцию.
