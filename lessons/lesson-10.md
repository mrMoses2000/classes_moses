# Занятие 10: «Устройство компьютера изнутри — архитектура фон Неймана, процессор, регистры и машинный такт»

Сценарий очного занятия для способного ученика 4 класса (55–60 минут)  
**Уровень сложности:** Профессиональный архитектурный (моделирование работы CPU, машинный такт, ассемблерные команды).  
**Траектория:** Этап 3. «Компьютер и Arduino» → Внутреннее устройство вычислительных систем и микроконтроллеров.

## 1. Место урока в общей траектории

- **Конечная способность из `LEARNING_VISION.md`:** Понимать, как программа оживает в кремнии: объяснять роли процессора, регистров, оперативной памяти (RAM), накопителя и шины данных; связывать строку кода на C с ассемблерными инструкциями процессора (`MOV`, `ADD`, `CMP`, `JMP`); понимать сущность тактовой частоты и машинного такта.
- **Текущий этап:** Рубеж перехода от программного кода к физическому кремнию (Этап 3: «Компьютер и Arduino»).
- **Прошлый освоенный навык (Занятия 6–9):** Ученик уверенно программирует на языке Си, понимает компиляцию, работу функций и область видимости.
- **Причина выбора темы:** Для большинства детей (и взрослых) компьютер остаётся «черным ящиком» с магией: код просто «как-то работает». Но настоящий инженер робототехники должен видеть сквозь кремний: как процессор считывает байты из памяти, как тактовый генератор отсчитывает миллиарды тиков в секунду, и как транзисторы складывают числа в регистрах. Это занятие снимает покров тайны перед подключением платы Arduino.

## 2. Главная учебная цель и проверяемый результат

- **Главная учебная цель:** Сформировать глубокую физическую и логическую модель архитектуры фон Неймана: разобрать четырёхтактный цикл процессора (**Выборка → Декодирование → Выполнение → Запись** / Fetch-Decode-Execute-Writeback) и сопоставить строку C с ассемблером.
- **Проверяемый результат (действие ребёнка без подсказки):**
  1. На схеме компьютера без запинки показывает потоки данных: накопитель (SSD) ➔ оперативная память (RAM) ➔ регистры процессора ➔ АЛУ (Арифметико-Логическое Устройство).
  2. В роли «живого процессора» вручную исполняет простейшую программу на карточках: перемещает число в регистр `AX`, складывает с числом из ячейки памяти и увеличивает счётчик команд `PC` (Program Counter).
  3. В терминале Linux выполняет команду `gcc -S` или `objdump`, находит в ассемблерном файле инструкции `movl` и `addl` и сопоставляет их со своим кодом на Си.

## 4. Практические задания с кодом и ассемблером

### Задание 1. «Дизассемблирование программы на C»
- **Исходный файл на C (`~/robot_lab/arch.c`):**
  ```c
  int calculate() {
      int a = 15;
      int b = 27;
      int result = a + b;
      return result;
  }
  ```
- **Команда генерации ассемблерного листинга:**
  ```bash
  gcc -S -O0 -fno-asynchronous-unwind-tables arch.c -o arch.s
  cat arch.s
  ```
- **Фрагмент ассемблерного кода (x86_64), который исследует ученик:**
  ```assembly
  movl    $15, -4(%rbp)      # Положить число 15 в память (переменная a)
  movl    $27, -8(%rbp)      # Положить число 27 в память (переменная b)
  movl    -4(%rbp), %edx     # Загрузить a в регистр EDX
  movl    -8(%rbp), %eax     # Загрузить b в регистр EAX
  addl    %edx, %eax         # Сложить EAX = EAX + EDX (АЛУ выполняет сложение!)
  movl    %eax, -12(%rbp)    # Сохранить результат в переменную result
  ```
- **Действие ученика:** Пальцем сопоставить каждую строчку ассемблера со строчкой в `arch.c`.

### Задание 2. «Анатомия условного перехода (if в ассемблере)»
- **Исходный файл (`~/robot_lab/branch.c`):**
  ```c
  int check_door(int key) {
      if (key == 777) {
          return 1;
      }
      return 0;
  }
  ```
- **Ассемблерный эквивалент:**
  ```assembly
  cmpl    $777, -4(%rbp)     # Сравнить значение key с числом 777
  jne     .L_WRONG_KEY       # Если НЕ равно (Jump Not Equal) -> прыгнуть на метку сбоя!
  movl    $1, %eax           # Иначе: вернуть 1 (успех)
  jmp     .L_EXIT
  .L_WRONG_KEY:
  movl    $0, %eax           # Вернуть 0 (отказ)
  .L_EXIT:
  ```
- **Открытие для ребёнка:** В процессоре нет слова «else». Есть только сравнение чисел и прыжок на другой адрес памяти!

### Задание 3. «Исследование оборудования Linux (lscpu & /proc/cpuinfo)»
- **Команды в терминале:**

  lscpu | grep "Model name\|CPU MHz\|Core(s)"

  - С какой частотой он сейчас работает?
  - Сколько гигабайт оперативной памяти доступно программам?

## 6. Дифференциация и развитие

- **Супер-вызов «Пирамида памяти»:** Нарисовать иерархию скорости:
  1. Регистры процессора (скорость: 0.5 наносекунды, размер: 100 байт).

## 7. Выходной вопрос и 4 критерия наблюдения

### Краткий выходной вопрос:
> *«Что делает процессор на каждом такте тактового генератора и как он понимает, какую команду выполнять следующей?»*  
> *(Ожидаемый ответ: «Он смотрит на счётчик команд (Program Counter), берёт из памяти очередную инструкцию, декодирует её, выполняет в АЛУ и сдвигает счётчик на следующий адрес»)*.

### 4 наблюдения преподавателя:
1. **Понимание роли регистров:** Не путает оперативную память и внутренние регистры CPU.
2. **Осознание ассемблера:** Способен найти инструкцию сложения `add` в ассемблерном файле.
3. **Механизм ветвлений:** Понимает, что `if/else` на уровне процессора — это сравнение и прыжок по адресу.
4. **Физическая картина:** Связывает абстрактную программу с тактовым генератором и питанием.
